# RAGWatch Dashboard

Interactive Streamlit dashboard that visualizes monitors, KPIs, and alerts generated by RAGWatch pipelines.

## MVP architecture at a glance

The dashboard follows a Model–View–Presenter (controller) separation to keep concerns isolated:

| Layer | Key modules | Responsibility |
| --- | --- | --- |
| **Model** | `model/repositories.py` | Loads and persists monitor metadata (`MonitorRepository`), KPI history (`KPIRepository`), and alert history (`AlertRepository`). |
| **Controller (Presenter)** | `controller/dashboard_controller.py`, `controller/state_adapter.py` | Orchestrates navigation, caches monitors, and exposes event handlers that mutate model state; wraps Streamlit session state via `SessionStateAdapter`. |
| **View (UI)** | `ui/dashboard_view.py`, `ui/monitor_create_view.py`, `ui/monitor_details_view.py` | Pure Streamlit components. They call the controller for data/events and never talk to CSVs directly. |

This split lets you iterate on UI without touching persistence, while the controller coordinates state transitions and data access.

## Prerequisites

1. Create and activate a virtual environment (optional but recommended):
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```
2. Install dependencies from the repo root:
   ```bash
   pip install -r requirements.txt
   ```

## Run the dashboard UI

From the repository root, launch Streamlit with:
```bash
streamlit run ragwatch_dashboard/main.py
```
The entry script bootstraps the controller and loads the MVP-based view. Streamlit’s hot-reload will pick up changes in the `controller/`, `model/`, or `ui/` packages automatically.

## Development tips

- **Add a new view** by creating another module under `ui/` that accepts a `DashboardController` instance.
- **Extend the data layer** by adding repository classes/functions under `model/` and injecting them via the controller constructor when needed.
- **Stateful interactions** should go through `controller.dashboard_controller.DashboardController` so you stay consistent with the MVP pattern and avoid accidental direct session-state access in the views.
